# Chat: the transcript and the composer

Generated by `python3 scripts/uiux_chat_inventory.py` — **never hand-edit this page**.

Chat's transcript names who is speaking and follows the stream only when the reader was already at the bottom; its composer says what Send will do, disables the button on the same predicate that writes the sentence, and keeps Clear undoable.

## Who is speaking

| Role | Label | Tone |
|---|---|---|
| `user` | You | `info` |
| `assistant` | Model | `ok` |

`CHAT_ROLES` is the only place a role gets words. Each turn is drawn with `data-role`, a header carrying its label and its number, and - for an answer - the model that produced it, above the answer rather than in a footer under it.

The transcript is `role="log"` with `aria-live="off"`: the pane re-renders on every token, so a live region here would read the whole conversation aloud, repeatedly. What *is* announced is the composer's reason, which changes only when the answer to "can I send?" changes.

## Following the stream, not the reader

Before this story the renderer ended with `box.scrollTop = box.scrollHeight`, so scrolling up during a reply dragged the reader back down on the next token. Now the pane asks `chatNearBottom()` *before* it re-renders and only follows when the reader was already there; otherwise it keeps the position and shows a **Jump to latest** control, which moves the scroll and the focus together.

The tolerance is 80px: close enough to the bottom counts as reading the newest turn.

## What Send will do

| Reason | When |
|---|---|
| `streaming` | a reply is in flight; Stop keeps what already arrived |
| `no-model` | `#chatModel` holds nothing usable, so Send is disabled |
| `runtime-offline` | a local model is selected and the telemetry verdict says the runtime is not answering |
| `tools-readonly` | tools are on: the route reads the workspace and cannot write to it |
| `ready` | Send will send, and the sentence says what Enter does |

`chatSendReason()` is the only predicate. The disabled button and the sentence under it both read it, so the composer cannot tell one story and do another. The sentence is a live region written only when its reason or the selected model changes.

`POST /api/chat/stream` reads `auto_unload, max_tokens, messages, model, reasoning_mode, skills, temperature, tools_enabled, workspace_dir` and runs the turn under policy `plan`, falling back to `WORKSPACE_ROOT` when no directory is sent — which is why the tools sentence says *read-only* and names the directory rather than claiming the tools will refuse.

## Clear, and the way back

Clear keeps the turns it removes and presents the recovery kind with **Undo**, because the transcript lives only in this page and the server cannot give it back. It is disabled when there is nothing to clear.

## Checks and limits

- the walk drives the transcript by writing chatHistory in the page, because the demo has no model runtime: it proves the rendering, the scroll rule, the composer predicate and the Clear undo, and it proves the failure surface by sending to a runtime that is not there - it does not prove a model's answer.
- the read-only claim is checked against the policy literal in app.py, not by attempting a write tool call.
- the pin tolerance (80px) is a judgement about a hand, not a measurement; it is recorded here so a later story can change it in one place.

`node scripts/chat_walk.mjs` drives the pane in a browser: it writes a transcript, holds the labels and the numbers against what it wrote, scrolls up mid-render and proves the pane does not follow, exercises the composer's reasons, clears and undoes, and sends to a runtime that is not there to photograph the failure surface.

## Regenerating

1. Change the pane in `static/index.html`, or a field in `POST /api/chat/stream`.
2. `python3 scripts/uiux_chat_inventory.py`.
3. `node scripts/chat_walk.mjs` against a running `scripts/demo_tour.py --serve`.
