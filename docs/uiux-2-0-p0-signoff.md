## The rollback path

One story, one merge commit. Revert the merge, not the individual commits, so the reverted tree is the tree that ran green before the story.

**Steps:**

1. Identify the story's merge commit: `git log --merges --oneline --grep 'UIUX-<story>' origin/main`.
2. Revert it: `git revert -m 1 <merge-sha>` on a branch, then open a pull request that names the story.
3. Regenerate the derived artifacts if the revert changed any pinned file: `python3 scripts/uiux_source_manifest.py`, `scripts/uiux_control_inventory.py`, `scripts/uiux_route_map.py`, `scripts/uiux_authorization_trace.py`, `scripts/uiux_preservation_signoff.py`.
4. Re-run the verification commands below and record their exit codes in the ledger.

**What a revert does not touch:**

* This package adds no database migration. A Git revert does not roll back durable database state; each future story must separately verify its migration and recovery effects.
* This package adds no privilege: the bearer token, host allowlist, origin check, rate limit and body-size limit are not changed by it.
* A revert changes tracked files in the target checkout, not arbitrary external workspaces. Review the target and protect uncommitted work before running it.

**Verification after a revert:**
