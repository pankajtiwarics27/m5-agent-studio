# UI and theme audit (before redesign)

## Structure and hierarchy

The application serves one HTML route (`/`); the six client-side panes are not separate URLs. `app.py` exposes API routes, not additional UI pages. The canonical frontend is vanilla HTML/CSS/JS in `static/index.html`; `studio.py` embeds it and is regenerated by `scripts/build_studio.py`. `design-system/m5-agentic-studio/MASTER.md` describes the current design system. There is no component framework or Tailwind. Shared CSS provides buttons, cards, modals, tabs, fields, badges and native `details`; the shell has a top bar, mode navigation, integration strip and telemetry rail. Keyboard shortcuts and a command palette exist.

| Pane | Class | Primary task/content | Supporting content and density |
|---|---|---|---|
| Start | secondary | First-run readiness and task | Preflight status, provider setup, global integrations and monitor |
| Harness | primary | Configure workspace/model and run a task; stream output | Session list, six settings, diff/compact, advanced workflows, integrations and telemetry all compete |
| Council | primary | Run or steer a council conversation | Session list, four role models, individual model controls, round and conclusion actions, telemetry |
| Pipeline | primary | Enter and run a four-stage prompt; inspect results | Presets, stage/status controls and telemetry |
| Compare | primary | Select models and compare responses | Synthesis, results grid, global controls and telemetry |
| Chat | primary | Send a model message and read replies | Persona, reasoning, tools, unloading and telemetry |

Secondary surfaces are dialogs for providers, skills, MCP, context tools, external harness, SDLC, diff, session creation and command search. Features are exposed by explicit controls, selected pane, backend-loaded models/integrations, session status and streaming state; there is no general feature flag framework. Do not infer availability from appearance or change settings as a layout side effect.

Top congestion priorities: **1. Harness** (session list + settings + workflow actions + stream + monitor); **2. Council** (sessions + roster + seat selectors + individual and round controls); **3. Pipeline** (prompt, stages, results, global strip and monitor). Compare and Chat also share the persistent strip and monitor.

Responsive rules: 1100px switches navigation to a horizontal row and monitor to an opt-in fixed side panel; 880/860px stacks the Harness/Council sidebars; 600/390px adjusts compact shell and dialogs. A narrow viewport can still lose work area height to stacked controls; fixed header height and scroll behavior need browser verification. The monitor button's markup starts expanded, but initialization corrects `aria-expanded` for narrow screens; resizing currently resets the panel state. Themes are dark by default and light via `body[data-theme]`, persisted in localStorage; legacy hardcoded colors remain light-only/dark-only risks.

### Violations and contrast

Legacy CSS, inline HTML and JS-generated markup contain hardcoded colors, translucent RGBA values and decorative status colors. The original root palette is overridden; it is not a second supported theme. Raw hex inventory below counts occurrences (including theme definitions), not just violations; there are 106 `rgb/rgba` occurrences. No arbitrary Tailwind classes are used. Search: `rg -n '#[0-9a-fA-F]{3,8}|rgba?\(|hsla?\(' static/index.html`.

Measured WCAG ratios from sRGB values: white on primary `#5969d8` 4.73:1; dark muted `#969da4` on card `#202428` 5.69:1; light muted `#687077` on white 5.03:1. Routine border against raised surface is only 1.44:1 dark and 1.38:1 light, insufficient when it alone defines a control boundary. Legacy inline `#e9d5ff` and `#fde68a` on white are 1.36:1 and 1.25:1, respectively; e.g. the integration labels can fail in light mode. These are representative measurements, not a complete contrast certification. Multiple primary-styled buttons appear simultaneously in Harness (new session and run), and multiple decorative status/accent hues appear in legacy UI. More comprehensive migration and real-browser checks are required.

## Verification baseline

`python scripts/check_frontend_syntax.py` passed; `python scripts/build_studio.py` succeeded with no drift. `pytest`, `ruff`, and `mypy` were not installed at audit time. UI-related coverage includes screenshot manifest validation (`tests/test_screenshots.py`), frontend syntax, and the Node auth helper (`scripts/test_ui_auth_helper.js`); screenshot capture requires Playwright and a running app. No browser-based interactive UI test suite was found. Manual visual/keyboard and contrast checks are not yet performed.
