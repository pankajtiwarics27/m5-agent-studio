## What this program changed

* One shell for six panes: a rail, a workspace and an inspector, with the tab registry, the shortcuts and the focus order recorded in `product/M5_2_0_UIUX_Source_Manifest.json`.
* One status vocabulary: nine states drawn from six tones, with every surface that speaks it enumerated in `product/M5_2_0_UIUX_Status_Components.json`.
* Design tokens as the only place a colour, radius, spacing or motion value is decided, with measured contrast floors (`product/M5_2_0_UIUX_Tokens.json`).
* Presentations for the empty, error and recovery cases, hosted rather than re-invented in each pane (`product/M5_2_0_UIUX_Presentations.json`).
* Journeys that report what the server actually did: the preflight's next action, durable task state in Harness and Pipeline, Council's deliberation, Compare's provenance, Chat's handoff to Harness.
* A preservation harness, an adversarial harness, a screenshot review and a documentation verification, each with its own generator and its own failing mode.

## What held

The program's non-negotiable invariants, and how each was kept:

* Endpoints, authorization contracts, approvals, event-cursor semantics, action admission, sandbox controls, workspace edits and session recovery: 21 capabilities across 6 panes, each with a prover, and no route removed.
* No new dependency, no CDN, no framework migration, no new outbound request.
* Untrusted text stays text: the adversarial inventory maps all 12 refusals and no pane decides authority locally.

## Known regressions

Recorded as they were found, each against the story that found it. None of them blocks the program; all of them are things a next session would want to know before it trusts a screen.

* UIUX-P4-01: The demo path's usage line still reports fabricated tok/s figures (29.5 / 42.1) and `record_perf` still stores them, because the flag the pane now reads (`demo`) does not stop the write; the pane no longer draws a figure for a demo reply, but the perf samples and the throughput card still count it. Recorded as an open risk for the runtime program rather than fixed inside a UI pull request.
* UIUX-P4-01: `syncUnifiedSelectors` rebuilds the seat pickers from the catalogue, which lists only resident local models; loading a model can therefore re-pick a seat whose model was not in the catalogue. The row stays true to what the round would post, but the operator's earlier choice can change under them.
* UIUX-P4-02: A pipeline view restored from the browser's checkpoint has no contract: the checkpoint stores what each seat produced (content, reasoning, usage), not what it was allowed, so the `Allowed` column reads `-` after a reload. Absence is drawn as absence rather than filled in, but the fix is to widen the checkpoint payload, which belongs to the recovery story that owns that format.
* UIUX-P4-03: The four Hall seat pickers are rewritten by a readiness refresh while a round runs: after the round the selectors can name models that did not answer (a cloud alias rather than the local models the summons posted). The verdict table is unaffected - it names the model each stored message carries - and the walk re-selects the models before its capture, but the pickers disagreeing with the transcript is a real defect this story found and did not fix; it belongs to the readiness refresh that rewrites them.
* UIUX-P4-03: Shared wording is a lexical measure: a seat that makes the same point in different words reads as `not in the decision` and is named under Dissent. The block says so in its basis line and prints the percentage, so a reader can discount it, but the pane cannot tell disagreement from paraphrasing and does not claim to.
* UIUX-P4-04: A comparison runs with `auto_unload: true`, so the local model it just compared can leave the catalogue: the checkbox strip is rebuilt from telemetry and stops offering it, while its card and its row stay on screen. The result is honest but confusing on a screenshot, and it is the picker's refresh behaviour (recorded under P4-01) rather than this story's; the walk's captures clip the run line, panels and results for that reason.
* UIUX-P4-04: The server has no per-panel error event: one provider exception ends the whole `run_stages` run, so a failed comparison always leaves the panels behind it `not run` rather than failing one and carrying on. The pane says exactly that and does not pretend to have a partial panel failure it cannot observe.
* UIUX-P4-04: Three of the ten states cannot be produced by the app in this environment: `queued` appears only between the click and the first `panel_start`, `empty` needs a runtime that finishes without words, and `stream ended` needs a socket that drops mid-run. They are asserted in the pane's vocabulary and in the inventory, and the fixture can produce six of the ten (answered, cut, demo, failed, stopped, not-run).
* UIUX-P4-05: `ttft` is the runtime's first-token figure for the stage as `app.py` computed it; for the fixture it is 0.04 s for every reply because the stand-in runtime sends `time_to_first_token: 0.04`. Nothing in the pane rounds or invents it, but a reader should not read the fixture's equal numbers as equal hardware.
* UIUX-P4-05: `prefill_tps` and `cached_tokens` travel in the usage object and are deliberately not printed: the pane has no reader for them that would not be a row of zeroes (the local path always sends `prefill_tps: 0.0`, `cached_tokens: 0`). They stay in the payload for a later story rather than being drawn as measured zeros.
* UIUX-P4-05: A demo reply still writes the invented 29.5 / 42.1 tok/s to `perf_samples` through `record_perf`; the pane no longer draws them anywhere, but the store still receives them, and that write belongs to the runtime program (recorded since P4-01).
* UIUX-P4-05: The arbiter's figures are the judge model's, so in the fixture they equal the panel's when the judge is the first model. That is the fixture answering one model the same way twice, not the pane echoing a row.
* UIUX-P4-06: The browser's copy restores the comparison, not the run: the model checkboxes are rebuilt from the live strip, so a restored comparison whose models the runtime has since unloaded comes back with those models listed in its cards (correct) but not ticked (also correct, and stated on the bar) - pressing Start would compare something else, which the bar says in as many words.
