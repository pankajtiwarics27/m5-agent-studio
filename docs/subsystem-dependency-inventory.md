## Runtime and authorization overview

- FastAPI app and startup boundary: [`app.py:L3378`](../app.py#L3378). Startup validates bind/auth/execution settings, initializes local SQLite, and creates the shared HTTP client; it does not issue model/provider requests.
- Shared HTTP request policy: [`app.py:L3454`](../app.py#L3454). All `/api/*` and `/v1/*` routes require bearer auth unless explicitly disabled on loopback; host allowlisting, state-changing Origin checks, request limits, and selected POST rate limits are also applied here.
- Route inventory: 96 method/path registrations, plus the separately listed static mount. Optional FastAPI `/docs` and `/openapi.json` are disabled by default in the app constructor at [`app.py:L3406`](../app.py#L3406); when enabled, those routes are public. `/redoc` is not registered.
- There is one operator trust domain: no user identity, tenant separation, or route-level RBAC is implemented. A valid bearer token is the primary API authorization boundary.
- Route authentication and tool authorization are separate boundaries: built-in, outbound MCP, and bundled inbound stdio MCP tool attempts pass through one deny-by-default policy and privacy-preserving audit boundary, including denials and approval rejections. The authenticated `/api/harness/approve` resolves pending harness approvals; explicit playground and inbound `tools/call` requests count as one-call intent but remain subject to registered-tool/server allowlists.

| Layer | Source | Decision / scope |
|---|---|---|

| Central tool execution and audit boundary | [`app.py:L11185`](../app.py#L11185) | Enforces action-class separation, grant provenance, task-state and lease-epoch validation, durable `runtime_actions` intent-before-effect and replay classification (`side_effect_ledger.DurableActionLedger`), privacy-preserving `tool_audit_events` start/finish, write-transaction discipline, and scoped anti-bypass admission tokens via `DurableActionBoundary`. |
| Harness approval decision | [`app.py:L6349`](../app.py#L6349) | Determines whether a human approval is required; centralized authorization independently enforces the decision at execution. |
| Harness execution boundary | [`app.py:L11773`](../app.py#L11773) | Routes built-in tool attempts through central authorization, durable audit, and the executor. |
| Approval request lifecycle | [`app.py:L7604`](../app.py#L7604) | Creates an in-process pending approval entry and records its request event. |
| Approval resolution API | [`app.py:L12497`](../app.py#L12497) | Authenticated operator resolves a pending approval by ID; there is no separate identity/role model. |

## Evidence and limitations

- API routes are enumerated from FastAPI's live registered route objects; endpoint source anchors are resolved from `app.py` on each generation.
- SQLite declarations are scanned from `app.py` and `runtime_persistence.py`. Generation fails on an undocumented or missing table and on an endpoint without subsystem/auth/source mapping.
- The HTTP auth column records shared boundary coverage plus notable route-specific policy; it does not assert per-user authorization, which the code does not implement.
- External destinations and process launches are documented as possible code paths. This generator does not contact them, and integration tests use local/mocked fixtures.
