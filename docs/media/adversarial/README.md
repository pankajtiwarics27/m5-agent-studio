# The refusal captures (UIUX-P6-02)

Nothing here was drawn by hand. Every file comes from one command, run against a throwaway demo
app that the command starts itself:

```bash
node scripts/adversarial_walk.mjs --theme dark  --screenshots docs/media/adversarial   # 16/16
node scripts/adversarial_walk.mjs --theme light --screenshots docs/media/adversarial   # 16/16
```

The walk attacks the running app and fails the run when a refusal is drawn as anything other than a
refusal, so a set that is out of date with the shell cannot be regenerated by accident: the run
that would produce these images would fail first.

| File | What it is |
|---|---|
| `adversarial-dark-apply-refusal.png` | A session whose policy is read-only `plan` refuses a worktree apply with **403**. The refusal is drawn inside the diff dialog where the button is, with the server's own sentence, a *Kept:* line and both actions, and the dialog stays open. |
| `adversarial-light-apply-refusal.png` | The same refusal in the light theme. |
| `adversarial-dark-narrow-apply-refusal.png` | The same refusal at 390x740, where the dialog stacks and both actions stay reachable. |
| `adversarial-light-narrow-apply-refusal.png` | The narrow refusal in the light theme. |
| `adversarial-dark-injected-503.png` | A **503** with `Authentication is unavailable; configure a token and restart Studio.` injected at the network layer, because the demo app always has a token configured. |
| `adversarial-light-injected-503.png` | The same injected 503 in the light theme. |
| `adversarial-dark-rate-limit.png` | A full rate window: **429**, the boundary's `Retry-After` as a countdown, and the Retry control disabled while the window is closed. |
| `adversarial-light-rate-limit.png` | The same in the light theme. |
| `adversarial-dark-before-apply-applied.png` | The same refused write on the **pre-story** handler, for contrast: the dialog has closed and an ok-tone toast says **"Applied!"**. |
| `adversarial-light-before-apply-applied.png` | The same before-state in the light theme. |

The last two were captured by running the same walk against the handler reverted to its pre-story
body (it reports 12/16 and names this check as the failure). They are the *before* half of the
story, not a state this tree can produce.

`python3 scripts/uiux_screenshot_review.py` inventories these files and checks that each theme is
the theme the filename claims; `docs/uiux-2-0-adversarial.md` maps every refusal to the check that
proves it.
