## The statuses

* `queued` (neutral) — the panel is behind the one running.
* `running` (busy) — the panel is streaming now.
* `answered` (ok) — the panel reported a reply the runtime finished.
* `cut` (warn) — the runtime stopped the reply at its length limit.
* `demo` (warn) — the local runtime was not answering, so the server wrote the reply itself.
* `empty` (warn) — the panel reported, and wrote nothing.
* `failed` (danger) — the provider failed; the message is quoted and nothing was saved for this panel.
* `stopped` (warn) — the reader stopped the comparison while this panel was running.
* `lost` (warn) — the stream ended before this panel reported.
* `not-run` (neutral) — the comparison ended before this panel's turn.

## What it refuses to claim

* cost - no price is configured for any model.
* judgement - the reader's criteria are theirs to judge.
* ranking - the table reports what each reply carried, not which reply is better.

## A known limit of the stream, drawn honestly

The server sends one `error` for the whole comparison: `WorkflowOrchestrator.run_stages` lets
a provider exception propagate, so a failure ends the run rather than failing one panel and
carrying on. The pane attributes that error to the panel that was running and says the panels
behind it never ran. A per-panel `stage_error` event is the orchestrator's change to make; this
pane reports what the stream can tell it.
