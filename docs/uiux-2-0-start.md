# Start readiness and the next step

Generated by `python3 scripts/uiux_onboarding_inventory.py` — **never hand-edit this page**.

The preflight decides what a first-run reader should do next and the Start pane prints that answer once: how far along, which step is next, and the action the server attached to it. The pane never recounts readiness, a step with no action is shown as following the next one, and Run is disabled only with a stated reason.

## What the preflight decides

`GET /api/onboarding/preflight` returns six steps in a fixed order (`auth`, `model-source`, `model-available`, `workspace`, `execution`, `first-task`), a `completed_count`, a `total_count`, a `ready` flag, a `blocked` flag and exactly one `next_step` — the first step whose status is neither `ready` nor `optional`. That is the server's answer to *what should a first-run reader click*.

The pane prints it once, above the list:

- **how far along** — `completed_count` of `total_count`, verbatim, never recounted in the browser;
- **which step is next** — its title and its detail, with `aria-current="step"` and a visible chip on that row;
- **what to click** — the action label the server attached to that step, wired to `runOnboardingAction()`;
- **why Run is off** — a visible hint naming the step that is holding it up, and the same text as the button's `aria-describedby`, because a disabled control with no stated reason is an invisible refusal.

A step the server gave no action is printed as following the next one rather than as a button that does nothing: `first-task` is `action-required` with no action whenever no model is selectable, and the thing to click in that state is the model step above it.

`next_step` is actionable in every case where it exists, which is the property the lead depends on: yes.

## What changed in the pane

| Before | After |
|---|---|
| six rows of equal weight; the reader picks | one lead naming the next step, plus `aria-current` on that row |
| `summary` in a pill, nothing else | `completed_count` of `total_count`, from the server |
| Run disabled with no reason | visible hint naming the blocking step and the same text as `aria-describedby` |
| a step with no action rendered as a bare row | printed as following the step marked next |
| Re-check removed the button that had focus, dropping it on `<body>` | focus returns to the lead (and to the composer when a chat error is dismissed) |

## Rules this artifact enforces

`--check` fails when the preflight names a next step with no action, when a step carries no title, when the lead stops reading `next_step`/`completed_count`/`total_count`/`ready`/`blocked`, when the pane recounts readiness or counts steps itself, when the `aria-current` row is not the server's next step, when the waiting line disappears, when Run loses its description or the hint stops naming the blocker, when clearing a presentation drops focus or hands it to a node that is about to be re-rendered, or when a state the renderer emits has no rule.

## Checks and limits

- the matrix runs the pure preflight module, so it covers every branch of the six step builders but not the app adapter that fills PreflightInputs from live state.
- a browser check cannot make a machine ready, so scripts/start_walk.mjs asserts the lead against the same API response the pane received rather than against an invented ready state.
- the readiness of a real install depends on the machine; this artifact says what the pane does with the answer.

The behaviour is measured by `node scripts/start_walk.mjs`, which reads the same response the pane read, asserts the lead and the marked row against it, checks that Run is off with a stated reason, presses the lead action and confirms it does what its label says, and then refuses the preflight and asserts that Re-check restores the list with focus back inside the pane instead of on `<body>`.

## Regenerating

1. Change a step builder in `onboarding_preflight.py` or the pane in `static/index.html`.
2. `python3 scripts/uiux_onboarding_inventory.py`.
3. `node scripts/start_walk.mjs --json` against a running `scripts/demo_tour.py --serve`.
