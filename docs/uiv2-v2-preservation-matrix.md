### `council_session_deletion` — classification `full__lifecycle_with_delete`

**Can a Council (hall) session be deleted or cleared through the API?**

- **delete**: `existing` — DELETE /api/hall/sessions clears every session except those running a summon (clear_hall_sessions_db(exclude=running)); DELETE /api/hall/sessions/{id} removes one and answers 409 while its summon is in flight. Both are true deletes (archived: false) and touch no workspace file, because a hall session owns none.
- **close**: `existing` — POST /api/hall/sessions/{session_id}/close still exists (app.py)
- routes: `DELETE /api/hall/sessions`, `DELETE /api/hall/sessions/{session_id}`, `GET /api/hall/sessions`, `GET /api/hall/sessions/{session_id}`, `POST /api/hall/sessions`, `POST /api/hall/sessions/{session_id}/close`, `POST /api/hall/sessions/{session_id}/message`, `POST /api/hall/sessions/{session_id}/summon`
