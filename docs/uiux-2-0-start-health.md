# Start: system health and the project workspace

Generated by `python3 scripts/uiux_start_health_inventory.py` — **never hand-edit this page**.

Start answers two questions with data the server already produces: whether this machine is working (runtime, memory, containers, workspace) and where a task will run. The health card renders the telemetry payload the monitor rail fetched, states whether that payload describes this machine or the demo's, and the workspace is the same setting the Harness uses - written through the same route and followed by a fresh preflight.

## Where the numbers come from

| Row | Source | When it cannot be read |
|---|---|---|
| Model runtime | `omlx_online` from `GET /api/telemetry` | the card says *not reachable* and the basis drops to unverified |
| Unified memory | `memory.omlx_gb + orbstack_gb + macos_apps_gb` over `total_gb`, plus `omlx.ceiling_gb` | rows say *not measured yet* |
| Containers | `docker.containers` and `docker.orbstack_detected` | *not measured yet* |
| Project workspace | `default_workspace` and `git_info` from the session payload | *not set*, with what the Harness will fall back to |

The telemetry route can answer with a simulated payload (`telemetry_source = `simulated_demo``) when no runtime responds, so the monitor rail still has something to draw. The card does not hide that: when it happens the basis is *unverified*, the summary pill reads **Demo data**, and the claim says the runtime and memory rows describe no machine while the workspace row still does.

That is the whole point of the evidence component: a number without its basis is a claim the reader cannot check.

## The three bases the card can show

| Basis | When | What it means |
|---|---|---|
| `measured` | a live telemetry payload | the runtime's own report, read just now |
| `unverified` | the simulated payload | the demo's numbers; the workspace row is still this machine's |
| `unavailable` | no payload at all | nothing here describes this machine |

## One workspace, two panes

Start reads the configured directory from the session payload and writes it through `POST /api/workspace/directory` (app.py:4803) — the same handler the Harness uses, which is why the Harness's own input updates when Start's does (`syncProjectDirInputs` owns the list of inputs that are the same setting).

After a change the pane re-reads the preflight, because a checklist that keeps saying the workspace is unwritable after it was set is worse than no checklist. A failure is not a toast: it is the error presentation, naming the cause and *which directory is still in force*, with Retry and a path to the Harness.

## Rules this artifact enforces

`--check` fails when the health card polls instead of reading the rail's payload, when the rail stops feeding it or keeps a payload after a failure, when a row reads something other than the payload, when the simulated case has no branch or the claim stops naming which rows remain real, when a tone is outside the shared vocabulary, when either card bypasses the status or evidence component, when the workspace is written any way other than the Harness's handler, when a change does not re-read the preflight, when a failure is lost, when either card is not painted at startup, when the claim's read time comes from a field the payload does not carry, when the card drops a row because it could not read it, or when a failed read presents no cause, no way to re-read, and no statement of what it did not affect, or when the failure box and the card footer print the same buttons at once.

## Checks and limits

- the memory and container rows are the runtime's own report, including when that report is the demo's; the artifact and the card both say so rather than smoothing it over.
- the workspace row is the session payload's default_workspace, so it describes what the Harness will use even when the runtime is unreachable.
- the browser walk checks the card against /api/telemetry on the host it runs on, so the simulated and the live branches are asserted by whichever one that host produces, and the other is asserted structurally.
- setting a workspace creates the directory if it is missing - that is the server's documented behaviour of POST /api/workspace/directory, not something the pane adds.

`node scripts/start_health_walk.mjs` reads `/api/telemetry` itself, holds the card's rows against it, asserts the basis matches what the host actually produced, sets a workspace through the pane and restores it, and refuses both routes to check the failure states.

## Regenerating

1. Change the pane in `static/index.html`, or a field in `GET /api/telemetry`.
2. `python3 scripts/uiux_start_health_inventory.py`.
3. `node scripts/start_health_walk.mjs` against a running `scripts/demo_tour.py --serve`.
